### 솔루션

1. 그러려면 데이터만으로는 부족하다
   - 필요한 데이터: 금융정보를 확인하는 사용자 중에서도 소비 판단·계획 유지에 어려움을 겪는 비율
   - 문제 정의 2, 7, 10번 데이터로 검증 가능
   - 제품 관점에서 Data와 Understand는 필수 기반이지만, 그 자체가 최종 가치가 되지는 않는다.
   - 사용자가 실제로 체감하는 가치는 데이터를 예산 기준으로 바꾸고, 현재 소비에 반영하고, 필요한 순간에 행동을 돕고, 그 결과를 다음 판단에 학습시키는 과정에서 만들어진다.

2. 정보 → 주의 → 판단 → 계획 → 행동 → 결과 → 회고 → 다음 판단
   - 필요한 데이터: 각 단계에서 실제로 사용자가 이탈하거나 어려움을 겪는 지점
   - 확인 항목:
     - 정보: 필요한 금융정보를 확인하는가
     - 주의: 중요한 소비 변화나 위험을 알아차리는가
     - 판단: 소비의 적절성을 판단할 수 있는가
     - 계획: 예산·목표를 세우는가
     - 행동: 계획대로 소비하는가
     - 결과: 계획과 실제 결과에 차이가 있는가
     - 회고: 소비 결과를 돌아보는가
     - 다음 판단: 회고가 이후 행동에 반영되는가
   - 이 8단계는 사용자가 경험하는 시간의 흐름이다.
   - 아래 12개 Layer는 이 흐름을 실제 제품 기능으로 구현하기 위한 구조다.
   - 각 Layer가 별도의 기능 목록으로 흩어지는 것이 아니라, 하나의 판단 루프 안에서 앞 단계의 결과를 다음 단계의 입력으로 넘겨야 한다.

   ![사용자 루프와 12개 제품 레이어](images/09_user_loop_and_12_layers.png)

| 사용자 루프 | 연결되는 핵심 Layer | 제품 역할 |
|---|---|---|
| 정보 | Data | 계좌 거래내역을 수집하고 소비 데이터를 정제한다 |
| 주의 | Understand, Track, Predict | 중요한 소비 변화와 예산 위험을 알아차리게 한다 |
| 판단 | Understand, Act, Goal | 현재 소비를 개인 기준과 미래 목표에 비춰 해석한다 |
| 계획 | Budget, Goal | 월 예산과 재무목표를 구체적인 기준으로 만든다 |
| 행동 | Track, Coach, Gamification, Act | 실제 소비 순간에 계획을 실행하도록 지원한다 |
| 결과 | Track, Predict | 잔여 예산, 소비 속도, 월말 예상 결과를 보여준다 |
| 회고 | Learn | 계획과 실제 행동의 차이, 경고 반응, 소비 변화를 정리한다 |
| 다음 판단 | Learn, Agent | 다음 예산과 코칭 기준을 개인별로 조정한다 |
| 전체 기반 | Financial Model | 소득·소비·자산·부채·목표를 장기 맥락으로 통합한다 |

3. 우리가 만들 것은 자산 대시보드가 아니라 이 루프다
   - 필요한 데이터: 기존 서비스가 정보 제공에는 강하지만 판단→계획→행동→회고의 연결은 부족하다는 경쟁 서비스 비교 데이터
   - 확인 항목: 소비 판단 지원, 행동 개입, 계획 대비 결과 피드백, 회고 및 다음 행동 지원 기능의 존재 여부
   - Data와 Understand는 사용자가 “무슨 일이 있었는지” 알게 하는 기반이다.
   - Budget과 Track은 그 정보를 “내가 정한 기준과 현재 상태”로 바꾼다.
   - Predict, Coach, Gamification, Act는 판단이 실제 소비 시점까지 유지되도록 돕는다.
   - Learn은 행동과 결과를 회고해 다음 예산과 코칭을 바꾸며 루프를 닫는다.
   - Goal은 소비를 미래의 선택권과 연결한다.
   - Agent와 Financial Model은 충분한 데이터와 행동 이력이 쌓인 뒤, 이 루프를 능동적이고 장기적인 개인 재무관리로 확장한다.

#### 핵심 기능 Layer

| Layer | 역할 | MVP 핵심 기능 | 고도화 기능 |
|---|---|---|---|
| **1. Data** | 소비 데이터 수집·정제 | 계좌 거래내역 수집, 소비 자동 분류 | 다계좌·카드 통합, 정기결제 탐지, 상점/시간대 데이터 정교화 |
| **2. Understand** | 소비 패턴 이해 | 카테고리별 월간 소비 분석 | 요일·시간대·상점·빈도·급여일 이후 소비 등 행동 패턴 분석 |
| **3. Budget** | 소비 기준 설정 | 카테고리별 월 예산 편성, 예산 진행률 시각화 | Flexible Budget, AI 기반 카테고리 예산 추천 |
| **4. Track** | 현재 소비 상태 반영 | 소비 발생 시 예산 자동 차감, 잔여 예산 표시 | 실시간 소비 속도, 주간 페이스 비교 |
| **5. Predict** | 미래 소비 예측 | - | Safe-to-Spend, 월말 예상 지출, 예상 초과액, 예산 소진일 |
| **6. Coach** | 행동 변화 유도 | 예산 임박·초과 경고 | 선제적 경고, 개인화 AI Coach, 단계별 Nudge |
| **7. Gamification** | 지속 사용·행동 강화 | 기본 목표 달성 피드백 | Streak, Recovery, Challenge, 보상 구조 |
| **8. Act** | 실제 의사결정 지원 | - | 예산 이동 제안, 소비 행동 단위 표현, What-if 구매 시뮬레이션 |
| **9. Learn** | 사용자 데이터로 다음 주기 개선 | 월간 소비 리포트, 다음 달 예산 추천 | 경고 반응·소비 변화까지 학습해 개인별 예산·코칭 자동 조정 |
| **10. Goal** | 소비와 재무목표 연결 | - | 저축·여행·비상금 등 목표 연계 |
| **11. Agent** | 능동적 재무관리 | - | 과소비 위험 선제 탐지, 예산 재조정 제안, 승인 기반 실행 |
| **12. Financial Model** | 장기 개인 재무 모델 | - | 소득·소비·자산·부채·목표를 통합한 Financial Digital Twin |

#### MVP 범위

MVP는 12개 Layer를 모두 구현하는 버전이 아니다. 핵심 가설을 검증하는 최소 폐쇄루프에 집중한다.

`Data → Understand → Budget → Track → Coach → Learn`

여기에 기본 목표 달성 피드백 형태의 Gamification을 더한다.

- Data: 계좌 거래내역 수집과 소비 자동 분류
- Understand: 카테고리별 월간 소비 분석
- Budget: 카테고리별 월 예산과 진행률
- Track: 소비 발생 시 예산 자동 차감과 잔여 예산
- Coach: 예산 임박·초과 경고
- Gamification: 기본 목표 달성 피드백
- Learn: 월간 소비 리포트와 다음 달 예산 추천

이 범위만으로도 다음 핵심 가설을 검증할 수 있다.

> 사용자가 소비 기준을 세우고, 현재 상태를 확인하고, 적절한 시점에 경고를 받고, 월말 결과를 회고하면 다음 달의 판단과 행동이 개선되는가?

#### 고도화 방향

- Predict와 Act는 현재 상태를 보여주는 앱을 미래 결과와 구매 선택을 지원하는 앱으로 확장한다.
- Goal은 예산을 단순 지출 제한이 아니라 저축·여행·비상금 등 미래 선택권과 연결한다.
- Coach와 Gamification은 일반 알림에서 개인화된 단계별 개입과 지속 행동 구조로 발전한다.
- Learn은 경고에 대한 반응과 실제 소비 변화를 학습해 예산과 코칭을 자동 조정한다.
- Agent와 Financial Model은 충분한 거래·반응·목표 이력이 축적된 이후에 구현한다. 이 순서를 지켜야 능동적 제안과 장기 시뮬레이션이 사용자 맥락에 기반할 수 있다.

#### 서사와 기능의 일관성

| 서사의 핵심 주장 | 기능 구조에서의 대응 |
|---|---|
| 핵심 금융정보는 이미 보인다 | Data와 Understand는 차별점이 아니라 출발점으로 둔다 |
| 사용자는 판단할 수 있지만 판단이 유지되지 않는다 | Track, Coach, Gamification, Act로 행동 시점의 실행을 지원한다 |
| 돈은 미래의 선택권이다 | Predict, Goal, Act로 현재 소비와 미래 결과를 연결한다 |
| 사람은 적게 쓰는 것보다 잘 쓰기를 원한다 | Budget과 Goal을 단순 절약이 아니라 개인 가치와 목표의 기준으로 사용한다 |
| 우리가 만들 것은 자산 대시보드가 아니라 루프다 | Learn이 결과를 다음 판단으로 되돌리고, Agent와 Financial Model이 장기적으로 루프를 개인화한다 |

따라서 제품의 핵심은 12개의 기능을 나열하는 데 있지 않다.  
**사용자의 소비 데이터가 판단 기준이 되고, 그 기준이 실제 행동에 개입하며, 행동 결과가 다시 다음 판단을 개선하는 구조를 만드는 것**이 핵심이다.
