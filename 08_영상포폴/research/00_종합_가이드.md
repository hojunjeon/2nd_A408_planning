## 0. 모델 선택 — Omni Flash 1.1로 할 때 알아둘 것

Flow에는 **Gemini Omni Flash 1.1**과 **Veo 3.1 (Lite/Fast/Quality)**이 있다. 이 프로젝트처럼 레퍼런스 이미지(Ingredients)로 캐릭터를 고정하는 작업에서는 선택지가 제한된다.

| 모델 | Ingredients | 길이 | 8초 크레딧 | 비고 |
|---|---|---|---|---|
| Veo 3.1 Quality | **X** | 4/6/8s | 100 | 레퍼런스 불가 → 이 프로젝트에서 사용 불가 |
| Veo 3.1 Fast | O (**8s만**) | 8s 고정 | 20 (Ultra 10) | 레퍼런스 기반 최고 품질 옵션 |
| Veo 3.1 Lite | O (8s만) | 8s 고정 | 10 (Ultra 5) | 드래프트용 |
| Omni Flash 1.1 | O | **4/6/8/10s** | 12 (360p는 6) | 720p, Video-to-Video 편집 가능 |

**권장 워크플로우**: Omni Flash 360p(6크레딧) 또는 Lite(10)로 타이밍·구도 검증 → 마음에 드는 컷만 **Veo 3.1 Fast**로 파이널. Omni Flash는 초당 크레딧이 싸고 10초 생성이 가능해서, 8초에 3비트가 과밀한 샷은 10초로 여유 있게 뽑은 뒤 트림하는 선택지도 있다. 단 최종 화질은 Fast가 위이므로 파이널은 Fast 권장.

주의: **한국 계정은 보이는 워터마크가 자동 적용**된다. 최종 출력 전 프로필 메뉴의 Visible watermarking 설정을 확인할 것. 1080p 업스케일은 구독자 무료이니 반드시 적용.

## 1. 크게 바뀌는 판단 3가지

### ① S04의 "KeyFin 로고"는 생성에 맡기지 않는다

Veo는 텍스트·로고 렌더링이 구조적으로 약하고, 오히려 가짜 자막을 생성하는 문제가 공식 보고됐다(MIT Technology Review). S04-B의 로고는:

- **1순위**: Veo로는 `3분할 → 점진 암전 → 문 열리며 M4 월드 리빌` 3비트만 생성하고, 완전 암전 구간(4.5~6초 부근)에 **NLE에서 로고 PNG를 합성**
- **2순위**: 로고가 합성된 스틸을 첫 프레임으로 Frames to Video에 넣어 "로고는 생성이 아니라 유지"시키기

현재 S04 프롬프트는 4비트(3분할→암전→로고→도어리빌)+로고 정확 렌더링을 요구하는데, 이건 실패 조건을 스스로 만든 셈이다. `s4_bad1.mp4`가 이미 존재하는 이유일 가능성이 높다.

### ② S12 역재생은 생성하지 않는다

Flow/Veo에는 실제 footage를 뒤집는 기능이 없다. "time rewinds" 프롬프트는 근사치일 뿐. **S01/S02 생성물을 NLE에서 실제 리버스**하는 게 유일하게 정확한 해법 — 콘티의 "실제 footage 재사용" 의도와도 일치한다.

### ③ 샷 연결은 텍스트가 아니라 프레임 인계

각 샷의 **마지막 프레임을 Save frame → 다음 샷의 첫 프레임(Frames to Video)**으로 넣는 게 샷 간 연속성의 정석이다. Extend는 "같은 액션 계속"용이라 컷 전환에는 안 맞고, 실행 모델도 Lite로 고정된다.

## 2. 프롬프트 작성 규칙 (이 프로젝트용)

### 기본 골격 — 13개 샷 공통

```
[타임스탬프 구간] [카메라] + [피사체=레퍼런스 역할 명시] + [동작 1개] + [환경/조명] + [스타일]
Audio: [환경음/SFX], no dialogue, no speech.
Negative prompt: subtitles, captions, on-screen text, text overlay, watermark, dialogue, speech
```

- `[00:00-00:03]` 타임스탬프 구간 지시는 **Google 공식 워크플로우**다. 다만 ±0.5~1초 흔들리므로 정확한 컷은 후반 트림.
- **비트당 동사 1개**가 상한선. 8초 3비트는 가능하지만 각 비트를 "지속 동작의 단계"로 써야 한다.

### 무언 연출 — "대사를 빼는" 게 아니라 "침묵을 묘사"

현재 S04의 `M5 MUST REMAIN COMPLETELY SILENT` + `NO lip movement` 나열 방식보다, 공식 권장은 **원하는 상태의 긍정 묘사**:

```
... M5 makes gentle eye contact, mouth closed, silent, a small closed-mouth smile.
Audio: soft ambient room tone, no dialogue, no speech.
+ negative prompt 필드: subtitles, captions, on-screen text, dialogue, speech, lip-sync
```

부정 지시는 2채널로: 본문은 긍정 묘사, negative 필드는 명사 나열. "NO X" 문장 단독 반복은 공식·커뮤니티 모두 약하다고 확인됨.

### Ingredients 제한 — 레퍼런스는 샷당 최대 3장

현재 S04는 `@KeyFin_S03_reference + @KeyFin_logo_reference + @M4_keyfin_room + @M5_keyfin_avatar` = **4장으로 초과**다. 로고를 후반 합성으로 빼면 자연히 3장으로 해소된다. 다른 샷도 `캐릭터 + 배경 + 핵심 소품` 3장 구조로 정리할 것. 더 많은 고정이 필요하면 Flow의 **Characters 기능**에 M1/M5/M2를 등록해 `@이름` 호출을 병행.

### 캐릭터/스타일 일관성

- 캐릭터 묘사 문자열을 모든 샷에서 **verbatim 재사용** (바꿔 쓰면 드리프트)
- 실사 파트 고정 문자열: `photorealistic, shot on 35mm film, muted cinematic tones`
- CGI 파트 고정 문자열: `stylized 3D CGI animation, soft volumetric lighting, purple-blue palette`
- 두 세계가 한 샷에서 만나는 전환부(S04-C)는 "모든 것이 REF-C/REF-D와 같은 stylized 3D 프로덕션"이라는 스타일 락을 유지 — 현재 프롬프트가 이미 잘하고 있는 부분

### 자막 뚫고 나올 때 대비

프레임 하단에 여유를 두는 구도로 생성 → 최악의 경우 하단 12~18% 크롭으로 무손실 복구 가능.

## 3. 샷별 액션 정리

| 샷 | 판단 |
|---|---|
| S01~S03, S05~S11 | 현행 3비트 구조로 생성 가능. 비트당 동사 1개 + Audio 줄 + negative 필드만 보강 |
| **S04** | 3비트로 축소(로고 제거). 암전 구간에 NLE 로고 합성. Ingredients 4장→3장 해소 |
| **S12-A** | 생성 시도 금지. S01/S02 클립을 NLE에서 리버스 재사용 |
| **S12-B/C** | 일반 생성. B는 S01-A와 같은 첫 프레임(선택 순간)을 재사용하면 "같은 상황 다른 판단"이 정확해짐 |
| **S13** | 타이포는 이미 후반 모션그래픽 결정됨 — 생성은 최종 키비주얼(S13-A)만 |

## 4. 크레딧 산정

- 파이널 Fast 8s × 13샷 = **260크레딧** (비-Ultra)
- 드래프트를 Omni Flash 360p(6크레딧)로 돌리면 검증 비용이 1/3 이하
- 정밀 연출 샷은 커뮤니티 기준 재생성 ~10:1 보고 — S04급 샷은 드래프트 검증을 생략하지 말 것
