# 셋업(Setup) 기획 발표 서사 구조
## `신비한 건축사전`형 구성

> 대상 기획: 소비 습관을 분석하고, 정기 지출 전에 결제 계좌에 필요한 돈을 미리 준비해 주는 생활 금융 관리 서비스  
> 서사 목적: 기능을 먼저 나열하지 않고, 사용자가 반복적으로 겪는 생활 금융의 이상 현상에서 출발해 문제를 재정의한 뒤 핵심 해결책을 자연스럽게 도출한다.

---

## 전체 서사 구조

`익숙한 상황 → 이상 현상 → 핵심 질문 → 당연한 첫 해석 → 첫 해석의 한계 → 두 번째 해석 → 두 번째 해석의 한계 → 문제 재정의 → 원리 공개 → 핵심 기능 공개 → 성공 상태 → 처음 질문 재해석`

---

## 서사에서 유지해야 할 핵심 논리

### 1. 기능보다 문제를 먼저 제시한다
초반에는 가상 예산, AI 분석, 자동 이체 기능을 직접 나열하지 않는다.  
사용자가 반복적으로 겪는 `잔액 확인 → 결제일 확인 → 수동 이체`라는 익숙한 행동을 먼저 문제로 인식시킨다.

### 2. 기존 해결책을 충분히 인정한 뒤 한계를 보여준다
가계부와 예산은 잘못된 기능이 아니라 각각 `기록`과 `계획`을 해결하는 유효한 방식이다.  
다만 예정된 결제와 계좌 준비라는 실행 문제까지 연결하지 못한다는 점에서 셋업의 차별점이 생긴다.

### 3. 핵심 반전은 '돈의 양'에서 '돈의 위치와 시점'으로 이동한다
셋업이 해결하려는 문제는 단순한 소득 부족이나 과소비가 아니다.  
사용자가 필요한 돈을 필요한 날짜와 계좌에 반복적으로 준비해야 하는 관리 구조 자체를 문제로 본다.

### 4. 분석 기능은 자동 준비를 위한 기반으로 연결한다
지출 자동 분류, 가상 예산, AI 소비 습관 분석을 독립 기능처럼 나열하지 않는다.  
사용자의 소비 상태를 이해하고 예정된 지출과 연결하기 위한 선행 단계로 설명한다.

### 5. 자동화 범위를 명확히 제한한다
셋업은 사용자의 모든 금융 결정을 자동화하지 않는다.  
사용자가 정한 계좌와 규칙 안에서 정기결제와 할부금에 필요한 돈을 사전에 준비하는 기능에 집중한다.

## 한 줄 서사

> **돈은 있는데 왜 계속 결제일마다 신경 써야 하는가 → 가계부와 예산만으로는 결제 준비까지 해결되지 않는다 → 문제는 돈의 양이 아니라 필요한 돈의 위치와 시점이다 → 소비를 이해하고 예정된 결제와 연결해 필요한 돈을 미리 준비한다 → 셋업은 생활 금융 관리 서비스다.**
