# 문제 정의 초안 — 오케스트레이터 직접 취합

작성일: 2026-08-22 (KST)
근거 범위: worker-A/B/C 원문 artifacts와 공식 원문을 다시 대조했다. 커뮤니티·SNS는 사용자 경험 신호로, 공식 포털·공고는 제도 사실로 분리했다.

## 출처 취합 원칙

- 제공자는 경쟁 서비스가 아니다. 온통청년·복지로·정부24·KINFA는 정책·복지·금융상품의 원문, 진단, 신청 연결, 상담 또는 데이터 API를 제공하는 연결원이다.
- 사실은 공식 원문/API/공식 영상에서 확인한 것, 경험은 공개 작성자의 보이는 발화, 추론은 두 종류를 연결한 설계 가설로 표기한다.
- 공개 사례는 자기선택 표본이다. 반복 신호는 확인했지만 발생률·성공률·금액 손실의 모집단 수치는 만들지 않는다.

## 검증 대상 문제 P-01 — 신청 전 eligibility·중복·순서 결정

**누가**
대학생·취준생·비정기 소득 알바생·사회초년생처럼 주소, 가구, 소득, 재학/재직 상태가 자주 바뀌는 청년.

**언제**
월세·수당·취업지원·정책형 금융상품을 신청하거나 기존 상품을 갈아타려는 순간.

**무엇을 하려 했고**
현재 받을 수 있는 제도를 찾고, 서로 배제되는 제도와 기존 수혜 이력을 피하면서 신청 순서를 정하려 했다.

**현재 어떤 방법을 쓰며**
온통청년·복지로·정부24·지자체/은행 페이지를 검색하고, 커뮤니티 비교표·블로그·스크린샷·상담을 참고한 뒤 필요한 서류를 수동으로 모은다. 이는 [온통청년](https://www.youthcenter.go.kr/youthIntro/introduce/introAbout), [복지로](https://www.bokjiro.go.kr/ssis-tbu/cms/pc/intro/intro/info/01/index.html), [정부24](https://www.gov.kr/portal/main)가 제공하는 발견·진단·신청 연결을 보완하는 행동이지 제공자를 대체하는 것이 아니다.

**어디서 실패하고**
정책명은 비슷해도 적용 지역·가구원·기준연도·현재/직전 소득·이전 수혜·신청기간·필요 첨부와 중복 제한이 각 원문에 흩어져 있다. 단일 검색·벡터 RAG 답변은 표 예외·상충 공고·변경 시점을 놓칠 수 있고, 예비진단을 최종 결정처럼 말하면 안 된다. 공개 글에는 “소득 조건 헷갈려서 신청 안 하는 애들 많더라”, “부모님 소득 때문에 컷날 수 있습니다”, “기존 계좌를 먼저 깨지 마세요” 같은 경고가 보인다([worker-A](worker-A.md)).

**무엇을 잃는가**
확정 금액·탈락률을 만들 수는 없지만, 확인되지 않은 정책을 신청하는 시간, 서류 준비·상담 비용, 신청 기회와 전환 순서를 잘못 선택할 위험, 불안과 결정 지연을 잃는다. 실제 지원금 손실액은 UNVERIFIED다.

**근거 수준**
경험 신호: 중간(서로 다른 공개 커뮤니티·영상/SNS에서 반복). 제도 사실: 높음(공식 원문). 전체 청년의 빈도·효과: UNVERIFIED.

## 검증 대상 문제 P-02 — 상태 변화 후 유지·중단·복구 결정

**누가**
정책 수혜 중이거나 신청 직후인 청년으로, 알바/취업·주소·가구·기존 수혜·월세 계약이 변할 수 있는 사람.

**언제**
소득 입금, 취업/퇴사, 이사·계약 변경, 가족 구성 변화, 예산 소진·서버 장애·반려 통지를 받은 뒤.

**무엇을 하려 했고**
지원을 계속 받을 수 있는지, 무엇을 언제 신고해야 하는지, 중지·재개·이의신청·대체 정책 중 무엇을 선택해야 하는지 확인하려 했다.

**현재 어떤 방법을 쓰며**
문자·포털 마이페이지·공고 PDF·상담기관을 다시 확인하고, 엑셀/메모/스크린샷으로 상태와 기한을 관리한다. [서울시 안내](https://soco.seoul.go.kr/coHouse/cmmn/file/fileDown.do?atchFileId=fba10a7affd347f189b4232d78f807fa&fileSn=3)는 접수 완료와 첨부 상태 확인을 요구하고, [복지로 청년월세 상세](https://www.bokjiro.go.kr/ssis-tbu/twataa/wlfareInfo/moveTWAT52011M.do?wlfareInfoId=WLF00004661&wlfareInfoReldBztpCd=01)는 지급 중지 후 재신청/잔여횟수 같은 운영 흐름을 설명한다.

**어디서 실패하고**
정책 변경·소득 반영 시점·중단 사유·신고기한·이의신청·환수/재개 규칙이 원문과 상태 기록에 분리되어 있어, “현재 상태가 바뀌었을 때 어떤 문서를 근거로 어느 기관에 무엇을 해야 하는가”를 한 번에 확인하기 어렵다. 단순 알림이나 단순 RAG는 기준일·버전·반증 문서를 보존하지 않으면 과잉 경고 또는 근거 없는 확신을 만들 수 있다.

**무엇을 잃는가**
신고·보완·이의신청 기한을 놓칠 위험, 지원 중단·재개 지연, 불필요한 상담 반복, 현금흐름 계획의 불확실성을 부담한다. 실제 환수·중단 금액은 UNVERIFIED다.

**근거 수준**
공식 운영 규칙: 높음(복지로/지자체 안내). 사용자 경험: 중간 이하(공개 개인 사례). 실제 발생률·금액: UNVERIFIED.

## 문제 범위에서 제외

- 온통청년·복지로·정부24·토스·뱅크샐러드는 경쟁사가 아니라 데이터·신청·연동·상담 제공자다.
- 할부 수수료 절감은 기획서의 후보 기능이지만, 이번 공개 조사에서 실제 사용자 문제와 금융 데이터 접근이 충분히 검증되지 않아 주 문제로 확정하지 않는다.
- 마이데이터 실계좌 자동연결, SMS 원문 수집, 카드사 스크래핑은 권한·법·개인정보가 확인되지 않아 설계 전제에서 제외한다. 금융위는 금융 마이데이터를 API 방식·동의·보안 심사 전제로 설명한다([금융위원회](https://www.fsc.go.kr/no010101/77182?curPage=124&srchBeginDt=&srchCtgry=&srchEndDt=%2F1000&srchKey=&srchText=)).

## 오케스트레이터 판단

P-01과 P-02는 같은 원문·사용자 상태·기한을 공유하지만 서로 다른 user moment다. 두 문제를 모두 후보로 유지하고, 설계 단계에서 신청 전 결정과 상태 변화 후 복구를 하나의 근거·버전·보류 가능한 흐름으로 묶을 수 있는지 비교한다. 기능명이나 AI 기술명으로 문제를 정의하지 않았다.

## 미검증/차단

- 공개 글의 연령·지역·소득과 전체 반복 빈도는 검증할 수 없다.
- 실제 탈락·환수·지원금 손실액, 신청 성공률, 상담 횟수, 시간 절감은 측정하지 않았다.
- 로그인·비공개 게시판·CAPTCHA·유료벽·개인 금융 계정은 접근하지 않았다.
- 공고의 현재 버전과 운영기관 판단이 충돌하면 운영기관 확인이 우선이며, 시스템은 UNVERIFIED/BLOCKED로 보류한다.
