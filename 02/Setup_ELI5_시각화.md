# Setup ELI5 시각화: 설득력과 기술력

대상 독자는 Setup을 처음 접하는 발표 심사위원과 팀원이다.

> Setup은 청년 금융 내비게이션이다.
> 신청 전에는 정책 자격과 순서를, 수혜 중에는 소득 조건을, 지출 후에는 할부 비용을 비교한다.
> 확정된 혜택과 사용자가 저축하기로 선택한 금액만 미래 자산 시나리오에 반영한다.

자동차 내비게이션에 비유하면 정책, 소득, 할부는 경유지이고 미래 자산은 목적지다. 아직 확인하지 않은 혜택과 절감액은 확정된 길이 아니므로 경로 계산에 넣지 않는다.

## 2. 설득력: 왜 이 제품이어야 하는가

```mermaid
flowchart LR
    P["문제<br/>신청 전·수혜 중·지출 후 판단이 흩어져 있다"]
    S["솔루션<br/>판단을 하나의 금융 내비게이션으로 연결한다"]
    F["기능<br/>순서·조건·비용·미래 차이·행동을 보여준다"]
    T["기술<br/>규칙과 계산식이 판정하고 LLM은 설명한다"]

    S -->|"왜?<br/>한곳에 모으는 것만으로 선택을 검토할 수 없기 때문"| F
```

|---|---|
| 문제 → 솔루션 | 정책 신청, 자격 유지, 할부 비용을 따로 보면 한 선택이 미래 자산에 미치는 영향을 알기 어렵다. 같은 시간축과 금액 기준으로 연결해야 비교가 성립한다. |
| 솔루션 → 기능 | 신청 순서, 소득 조건, 비용 차이, 미래 변화, 실행 계획을 차례로 보여줘야 사용자가 선택을 검토한다. |
| 기능 → 기술 | 자격과 금액은 재현 가능해야 한다. 규칙과 계산식이 판단하고 LLM은 구조화된 결과의 분류 후보와 설명만 맡는다. |

| 문제와 해결책 | 연결된 기능 | 현재 근거 |
|---|---|---|
| 금융관리 행동과 반복 소비 P1~P3 → 지출 케어 | F1~F3, C1, C2 | A~C 등급 근거가 섞여 있다. P2는 솔루션 표의 문제 매핑에서 빠져 있다. |

## 3. 기술력: 실제로 만들 수 있는가

```mermaid
flowchart LR
    I["입력<br/>프로필·거래·소득·할부 조건"] --> R["규칙·계산식<br/>정책 조건·임계값·수수료·미래가치"]
    R --> O["근거가 붙은 결과<br/>출처·기준일·입력값·계산식"]
    O --> L["LLM<br/>분류 후보·사람이 읽을 설명"]
    L --> U["사용자<br/>시나리오 비교·반영 여부 선택"]
```

## 4. 5주·6인 판단

W1에 실제 카드 파일, 정책 API 응답, 공고 조항, 소득 산정 기준일, 카드 계산식 1건을 재현한다. 재현에 성공하면 W2~W5에 핵심 흐름을 구현하고 사용자를 검증한다. 재현하지 못하면 검증한 정책 1~3종과 할부 예시 1건만 남겨 시연 범위를 줄인다.

현재 문서의 88시간 추정치는 C3-B 소득 컷오프와 C4-B 할부 비교를 제외한 값이다. 두 기능은 MVP 필수 범위지만 공수가 없다. 전체 MVP가 5주 안에 가능하다는 결론은 아직 `[UNVERIFIED]`다.

## 심사에서 전달할 세 문장

1. Setup은 정책, 소득, 할부를 따로 보여주는 앱이 아니라 세 판단을 미래 자산 시나리오 하나로 연결하는 청년 금융 내비게이션이다.
2. 자격과 금액은 규칙과 계산식이 처리하고 LLM은 분류 후보와 설명만 맡기 때문에 결과의 근거를 다시 확인할 수 있다.
3. 현재 가장 큰 위험은 정책 조항, 소득 기준, 카드 계산식, C3-B·C4-B 공수가 확인되지 않았다는 점이며 W1 검증 게이트를 통과한 범위만 MVP로 구현한다.
