# 📄 [기획서] 사회초년생 & 청년 맞춤형 혜택 & AI 자산 케어 모바일 플랫폼: 셋업 (Setup)

## 1. 프로젝트 개요 (Overview)

* **프로젝트명**: **셋업 (Setup)** - 청년층(대학생·취준생·사회초년생)을 위한 AI 기반 금융 자립 & 지출 케어 내비게이션
* **팀 구성 및 R&R (총 6인)**:
* **Frontend (2명)**: React Native / TypeScript (또는 JavaScript) 기반 **Android 전용** 모바일 앱 개발 (스토어 심사 없이 APK 직접 배포)
* **Backend (2명)**: Spring Boot / Java 기반 RESTful API 서버, 대용량 Batch Pipeline, Database 설계
* **AI · Data (2명)**: Agentic RAG 파이프라인 구축, 공공 정책 자동 수집 배치, SMS 문맥 파싱(Regex) 알고리즘


* **타겟 사용자**: **20대~30대 청년층 전반 (대학생, 취준생, 비정기 소득 알바생, 사회초년생 직장인)**
* *Unearned / Low-Income Thin-Filer (고정 소득이 없거나 금융 이력이 부족해 금융·정책 케어가 절실한 청년층)*


* **핵심 미션**:
1. 복잡하고 파편화된 **정부/지자체 청년 정책 지원금(월세, 수당, 장학금, 세제 혜택 등)의 중복 수혜 여부를 판별하고, 소득 유무에 맞춘 최적의 신청 순서(로드맵)를 제시**
2. 지원금 수혜로 아낀 자금과 예·적금을 결합했을 때의 **미래 자산 성장 시뮬레이션 및 자격 박탈 방지 가이드** 제공
3. 카드/학원비/교재비 할부 사후 관리 및 수수료 절감을 메우는 **DIFM(Do It For Me) AI 케어 Agent** 구축

## 2. 문제 정의 및 해결 방안 (Problem & Solution)

### 🔴 Problem (기존 서비스의 한계)

1. **청년 정책의 중복 수혜 제한 및 신청 순서의 혼란 (핵심)**:
정부/지자체 청년 정책 지원금(청년월세지원, 청년수당, 국민취업지원제도, 청년미래적금 등)은 **동시 수혜가 불가능하거나 선후 관계가 존재**함에도, 단순 나열식 정보만 제공되어 청년들이 잘못 신청했다가 혜택을 날리거나 중복 탈락함. (예: 서울시 청년수당과 서울시 청년월세지원은 상호 배제, 국민취업지원제도 참여자는 청년수당 신청 불가)
2. **소득 기준 초과로 인한 '정책 지원금 중단·반납' 리스크**:
알바비나 단기 소득이 조금 증가했다가 **정책 소득 기준(예: 중위소득 60% 이하)을 미세하게 초과하여 수백만 원 상당의 지원금 자격이 박탈**되는 억울한 사례 빈번.
3. **지출/할부 사후 관리 공백 및 수수료 낭비**:
노트북/학원비/교재비 및 신용카드 결제 시 발생하는 **유이자 할부 수수료**의 실제 액수를 파악하지 못해 불필요한 금융 비용이 지속적으로 새어나감.

### 🟢 Solution (셋업의 차별화된 해결책)

1. **청년 정책 수혜 극대화를 위한 '단계별 최적 신청 로드맵 Engine'**:
유저의 프로필(소득 상태, 지역, 나이, 주거 형태)을 분석하여 중복 수혜 금지 조항을 우회하고 혜택 금액을 극대화하는 **개인 맞춤형 정책 타임라인 가이드** 제공.
2. **정책 자격 유지 '지출 & 소득 컷오프(Cut-off)' AI 알림**:
유저의 누적 소득 및 결제 문자를 실시간 추적하여, **알바 수입 등으로 인해 정책 수혜 자격이 박탈되지 않도록 사전 위험 경고(Warning) 및 행동 가이드** 제공.
3. **AI 기반 '카드 할부 & 수수료 최적화 Agent'**:
스마트폰 결제 문자/PUSH 수신 즉시 **유이자 할부 수수료를 계산하고, 정책 지원금 입금 시점과 연계한 중도 상환/슬림할부 스케줄**을 자동 생성하여 금융 비용 최소화.

> * **잘못된 접근**: 서울시 청년월세지원과 서울시 청년수당을 동시에 신청하려다 **서울시 두 사업 간 상호 배제 조항**에 걸리고, 청년수당은 '최종학력 졸업 후 미취업자' 요건 미충족(재학 중)으로 탈락.

## 3. 핵심 AI 기능 상세 명세 (Core AI Features)

### 🤖 ① [Agentic RAG] 공공 공고문 자동 파이프라인 & Layout-Aware 구조화

* **100% 자동화 수집 파이프라인 (Data Pipeline)**:
* 매일 새벽 Spring Boot Batch가 온통청년/공공데이터포털 API를 호출하여 신규 정책 메타데이터(정책명, 자격요건 텍스트, 주관기관 URL) 자동 감지.
* 온통청년 API는 첨부파일 URL을 직접 제공하지 않으므로, API가 주는 **주관기관 공고 페이지 URL을 따라가 첨부파일(PDF/HWP)을 수집하는 2차 크롤링 단계**를 둠. 공고문 본문은 PDF 병행 게시가 관행이므로 **PDF 우선 → HWPX → HWP 순 폴백** 전략 적용.
* S3 버킷 수집 및 Vector DB(FAISS/Chroma) 자동 인덱싱 구축으로 **운영진 개입 0% 구현**.


* **Layout-Aware Vision Parser (LlamaParse / Unstructured)**:
* 단순히 글자만 긁어오는 일반 PDF 파서와 달리, **Computer Vision AI**를 통해 공고문 내 '조건표(Table)'와 '지원금 산정 공식 박스'의 시각적 구조를 완전히 이해.
* 표 데이터를 Markdown Table 및 JSON 수식으로 정밀 변환하여 **LLM의 환각(Hallucination) 없이 유저 자격 조건을 100% 정확하게 대조 연산**.



### 🤖 ② [할부 최적화 Agent] 실시간 수수료 절감 & 상환 스케줄러

* **수수료 절감 연산 알고리즘**:

$$수수료 = \text{잔여원금} \times \text{할부수수료율(\%)} \times \frac{\text{날짜수}}{365}$$


* **동작 프로세스**:
1. **SMS/PUSH 감지**: 유저가 120만 원(6개월 할부) 결제 문자 수신 시, FE 앱이 백그라운드 감지 후 BE로 파싱 데이터 전송.
2. **AI 연산 및 지원금 연계**:
* 단순 6개월 유지 시 수수료: **37,500원**
* 2개월 뒤 예정된 청년수당(50만 원) 입금 시점에 맞춰 **50만 원 중도 상환 플랜 적용 시 수수료: 14,200원 (23,300원 절감)**


3. **AI PUSH 가이드 발송**:
> *"방금 결제하신 120만 원, 10월 청년수당 입금 시 50만 원을 중도 상환하시면 **할부 수수료 23,300원을 즉시 아낄 수 있습니다.** [AI 상환 가이드 보기]"*





### 🤖 ③ [지출 & 소득 컷오프 Agent] 정책 수혜 자격 유지 위험 경보

* **소득 상한선(Cut-off) 모니터링**:
* 유저가 현재 수혜 중이거나 3개월 내 신청 예정인 정책의 '소득 자격 기준(예: 중위소득 60% 이하, 반기 소득 120만 원 이하)'을 AI가 상시 트래킹.


* **실시간 누적 소득 연산 및 위험 알림**:
* SMS/알림톡으로 수신되는 알바비, 단기 소득, 프리랜서 입금 내역을 자동 합산.
* 이번 달 추가 소득으로 인해 정책 기준을 초과할 위험이 감지되면 선제적 PUSH 알림 발송.


* **AI PUSH 가이드 발송**:
> "⚠️ **[청년월세지원 자격 유지 경보]**
> 이번 달 알바비가 **15만 원 이상 추가 입금될 경우**, 소득 기준을 초과하여 **총 240만 원의 월세 지원금이 중단**될 위험이 있습니다. 이번 달 대타 근무는 다음 달로 조율하시는 것을 권장합니다."

## 4. 데이터 수집 및 마이데이터 제약 극복 전략

### ⚠️ 마이데이터 법적 제약 및 현주소

* 정식 마이데이터 사업자 라이선스가 없는 프로젝트 팀은 카드사/은행의 실제 상용 API를 직접 호출하는 것이 법적으로 불가능함 (스크래핑 전면 금지).

### ❓ 백그라운드: 왜 마이데이터 연동이 막혀있는가?

1. **법적 제약 (마이데이터 사업자 라이선스)**:
정식 마이데이터 서비스(토스, 뱅크샐러드 등)를 하려면 금융위원회로부터 '신용정보관리업(마이데이터) 라이선스'를 취득해야 합니다. 자본금 5억 원 이상, 보안 설비, 법인 사업자 등록이 필수이므로 학생/프로젝트 팀은 **법적으로 상용 카드사 API에 접근할 수 없습니다.**
2. **기술적 제약 (마이데이터 서비스 내 스크래핑 금지)**:
2022년 1월부터 **마이데이터 사업자의 마이데이터 서비스 안에서는 스크래핑이 금지**되고 표준 API만 허용됩니다. 다만 CODEF 등 상용 중계 API가 제공하는 '본인 인증 기반 조회 대행' 상품은 마이데이터 서비스와 별개 영역에서 합법적으로 운영 중입니다(아래 CODEF 참고).

### 💡 팀원 및 심사위원 설득을 위한 데이터 해결책 (이원화 전략)

```
[1. 발표 & 심사용 (Technical Proof) : CODEF Sandbox/Demo 연동]
 ├─ 이유: 실제 카드사 서버 접근은 법적으로 막혀있으나, 백엔드의 데이터 가공 기술력을 증명해야 함.
 ├─ 방식: CODEF Sandbox(무료·고정 더미 응답)로 상용 카드 명세 규격의 JSON(회차별 원금/수수료)을
 │        수신받아 완납 타임라인 및 수수료 파이프라인을 처리함.
 └─ 실연: 필요 시 CODEF Demo 환경(무료 신청, 3개월간 일 100회)으로 팀원 본인 카드의
          실데이터 조회 시연까지 가능. (정식 전환은 사업자 심사 후 엔드포인트 교체만으로 가능)

 ├─ 1. 정책 데이터 : 온통청년 오픈API / 공공데이터포털 청년정책 API (개인 개발자 신청 가능)
 ├─ 2. 소득/거주지 프로필 : 유저 자기입력 + 시연용 mock (공공 마이데이터는 법인 전용 → 아래 검증 결과 참고)
 ├─ 3. 모바일 App SMS / Push 알림 파서 : Android 권한 기반 결제/입금 문자 자동 파싱 (지출 & 소득 자동 수집용)
 └─ 4. Step-by-Step 3초 간편 진단 UI : 인증 부담 유저를 위해 카드사/금액/개월수 직접 입력 도구 제공

```

### 🔍 공공 마이데이터 API 접근성 검증 결과 (2026.8 확인)

* **공공 마이데이터(mydata.go.kr) 이용기관 등록은 학생 팀 불가**: 가입 시 사업자등록번호/법인등록번호 자동 검증이 필수이고, 전담관리자 지정 + 한국신용정보원 서류 심사·현장실사 + 행안부 적격 심사(약 3개월)를 거쳐야 함. 전자문서지갑(전자증명서) 수취기관도 동일하게 기관 단위 등록 필요.
* **반면 정책 데이터 API는 즉시 가능**: 온통청년 오픈API는 개인 회원 가입만으로 인증키 신청 가능하고, 공공데이터포털의 청년정책 API는 개발단계 자동승인이라 당일 키 확보 가능.
* **소득 실데이터가 꼭 필요한 경우의 대안**: CODEF Demo의 간편인증(카카오/PASS) 기반 홈택스 소득금액증명 조회 대행(3개월간 일 100회 무료). 그 외에는 자기입력 + mock이 표준적 접근.

### 💡 해법: CODEF Sandbox란? (2026.8 검증 완료)

> **"실제 카드사 운영 서버에 연결할 수는 없지만, 상용 금융 데이터 중계 API의 실서비스와 동일한 규격으로 백엔드 파이프라인이 작동함을 증명하는 기술적 우회책"**입니다.

#### ① CODEF 중계 API와 Sandbox란?

* **CODEF**는 ㈜헥토데이터(헥토파이낸셜 자회사, 구 코드에프)가 운영하는 국내 대표 금융 데이터 수집·중계 API 플랫폼. 은행 20개·카드사 14개·공공기관(홈택스, 정부24 등)의 데이터를 사용자 인증 기반 조회(스크래핑 + 일부 기관 제휴 API)로 수집해 **자체 표준 규격(`res*` 필드)의 JSON**으로 제공. 운영사는 금융위 마이데이터 본허가 사업자이기도 하나, CODEF API 상품 자체는 마이데이터 표준 API와는 별개의 자체 규격임.
* **3단계 환경**:

| 환경 | 반환 데이터 | 비용/한도 | 가입 요건 |
| --- | --- | --- | --- |
| **Sandbox** | 상품별 고정 더미(mock) 응답 | 무료, 공개 키 SDK 내장 | 회원가입만으로 즉시 |
| **Demo** | 본인 인증 기반 **실데이터** | 무료, 3개월간 일 100회 | 무료 신청 즉시 전환 |
| **정식** | 실데이터 | 유료 (월 구독 + 사용량) | 사업자 정보 + 심사 (3영업일) |

* **카드 관련 상품**: 개인 승인내역, 청구내역(명세서), 한도조회, 보유카드 등 — 응답에 할부개월(`resInstallmentMonth`) 등 할부 관련 필드 포함.

#### ② 왜 이것이 기술적 증명(Proof)이 되는가?

상용 중계 API가 백엔드로 넘겨주는 카드 명세 데이터(JSON)는 다음과 같은 **'회차별 원금/수수료 배열'** 형태입니다.

```json
// CODEF 카드 청구내역 규격을 단순화한 예시
// (실제 필드명은 res* 접두사 — developer.codef.io 개발가이드 기준으로 확정 필요)
{
  "cardName": "KB국민 청년대로 카드",
  "approvedAmount": 1200000,
  "totalInstallmentMonths": 6,
  "currentInstallmentRound": 2, // 현재 2회차
  "monthlyDetails": [
    { "round": 1, "principal": 200000, "fee": 12500, "paymentDate": "2026-07-25" },
    { "round": 2, "principal": 200000, "fee": 10000, "paymentDate": "2026-08-25" },
    { "round": 3, "principal": 200000, "fee": 7500,  "paymentDate": "2026-09-25" },
    { "round": 4, "principal": 200000, "fee": 5000,  "paymentDate": "2026-10-25" },
    { "round": 5, "principal": 200000, "fee": 2500,  "paymentDate": "2026-11-25" },
    { "round": 6, "principal": 200000, "fee": 0,     "paymentDate": "2026-12-25" }
  ]
}

```

* **설득 논리**:
"우리가 법적 사업자가 아니어서 실제 유저의 카드사 데이터를 직접 뽑아올 수는 없지만, **상용 금융 데이터 중계 API(CODEF)의 실서비스와 동일한 카드 명세 규격 JSON을 Sandbox/Demo로 수신하고, 이 배열(Array) 데이터를 백엔드에서 파싱하여 회차별 수수료 및 완납 타임라인으로 시각화하는 파이프라인을 구축**했습니다. Demo 환경에서는 본인 인증으로 팀원의 실제 카드 데이터 조회 시연까지 가능하며, 정식 계약(사업자 심사, 3영업일)만 거치면 **엔드포인트 전환만으로 실데이터에 즉시 연동되는 아키텍처**입니다."

## 5. 파트별 기술 아키텍처 및 역할 분담 (R&R)

### 🔹 Frontend (2명) - `React Native` + `TypeScript` (or `JS`)

* **Android 전용 모바일 앱 구현**: React Native 기반 Android 앱 개발. 스토어 심사(Google Play SMS 권한 제한) 대신 **APK 직접 배포(사이드로드)**로 시연·테스트. (iOS는 OS 정책상 서드파티 앱의 SMS/타 앱 알림 접근이 불가하여 지원 범위에서 제외)
* **Native Module 연동**: Android `SmsReceiver` / `NotificationListenerService` 기반 결제/입금 문자·PUSH 알림 자동 수신 처리.
* **시각화 Dashboard**: 소득 형태별 맞춤 대시보드, 정책 신청 순서 타임라인 UI, 할부 수수료 절감 시뮬레이션 Chart (`victory-native` 등 RN 차트 라이브러리).

### 🔹 Backend (2명) - `Spring Boot` + `Java`

* **공공 API 크롤링 & Batch Pipeline**: 매일 새벽 정책 공고 및 첨부파일(HWP/PDF) 자동 수집 파이프라인 구축.
* **정책 로드맵 & CODEF Sandbox/Demo 연동**: 정책 간 중복 수혜 조건 필터링 알고리즘 및 CODEF 카드 명세 규격(`res*`) JSON 기반 가상 원장 엔진 개발.
* **캐싱 및 PUSH 메시징**: Redis Caching 적용 및 FCM 기반 실시간 PUSH 알림 연동.

### 🔹 AI / Data (2명) - `Python` + `LangChain` / `FastAPI`

* **Agentic RAG & Vision Parsing**: LlamaParse/Unstructured 기반 공고문 표(Table) 구조화 및 자격 조건 자동 인덱싱. (LlamaParse는 HWP를 직접 지원하지 않으므로 **PDF 우선 파싱, HWP 단독 공고는 HWPX/HWP 전용 파서로 텍스트 추출 후 처리하는 폴백 경로** 운영)
* **할부 수수료 & 컷오프 Engine**: SMS 정규식 파싱 데이터 기반 할부 중도상환 최적화 수식 연산 및 소득 컷오프 위험 감지 모델 개발.
