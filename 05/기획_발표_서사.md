# 기획 발표 서사

발표 제목: 내 통장을 읽고 먼저 말을 거는 금융 비서

부제: 소비를 알아보고 필요한 행동까지 챙기는 캐릭터 AI 서비스

예상 길이: 약 7분 10초

상태: 설계안

> 「신비한 건축사전」의 고유 문장이나 소재는 가져오지 않는다. 익숙한 장면에서 시작해 두 번의 해법과 실패를 거친 뒤 관점을 바꾸고, 작동 원리와 약점을 설명한 다음 첫 장면으로 돌아오는 흐름만 참고한다.

## 1. 발표의 핵심 반전

> 캐릭터가 금융 정보를 보여주는 데서 끝나지 않고, 지금 필요한 행동을 묻고 허락받은 일까지 처리합니다.

## 2. 전체 흐름

```text
익숙한 장면: 아침에 캐릭터가 화가 나 있는데 이유를 모른다
→ 모순: 내 소비를 표현하지만 정작 내가 무엇을 해야 하는지는 알려주지 않는다
→ 첫 해법: 잔액과 예산, 소비 내역을 한 화면에 모은다
→ 실패: 정보는 모였지만 해석과 판단은 여전히 사용자의 몫이다
→ 두 번째 해법: AI가 소비를 분석해 말풍선으로 알려준다
→ 실패: 설명만 늘어나면 또 하나의 알림이 될 뿐이다
→ 문제 재정의: 필요한 것은 정보를 보여주는 캐릭터가 아니라 금융 행동을 돕는 비서다
→ 중앙 반전: 캐릭터가 상태를 설명하고 행동을 제안하되 실행 전에는 반드시 허락을 구한다
→ 작동 원리: 상태 확인 → 설명 → 제안 → 승인 → 실행 → 결과 확인
→ 2차 문제: 캐릭터가 친근할수록 사용자가 AI를 과신할 수 있다
→ 보정: 계산과 설명을 분리하고, 모호한 데이터는 추측하지 않으며, 실제 행동은 승인 뒤에만 처리한다
→ 검증: 데모 데이터와 모의 실행으로 한 흐름을 끝까지 확인한다
→ 첫 장면 회수: 이유를 몰랐던 캐릭터의 행동이 설명과 선택지로 바뀐다
```

## 3. 슬라이드별 발표안

| 5 | 1:45~2:10 | 그럼 AI가 설명하면 될까요? | 캐릭터 말풍선에 전월 대비 소비와 예산 소진 예상일이 뜬다. | “그래서 AI가 소비를 분석해 설명하도록 합니다. 이번 달 카페 지출이 지난달보다 늘었는지, 지금 속도라면 식비 예산을 언제 다 쓸지, 남은 기간에 얼마를 줄여야 하는지 캐릭터가 말해 줍니다.” |
| 6 | 2:10~2:35 | 설명만 늘면 알림도 하나 더 늘어납니다 | 비슷한 말풍선이 쌓이고 사용자가 닫는 장면. | “문제는 설명을 읽은 다음입니다. ‘식비를 줄여야 한다’는 말을 들었어도 사용자는 다시 앱을 나가 직접 행동해야 합니다. 자동이체 계좌에 돈이 부족해도 안내만 받고 끝난다면, 캐릭터는 말이 조금 더 쉬운 알림에 머뭅니다.” |

| 8 | 3:00~3:25 | 캐릭터가 먼저 묻습니다 | 자동이체 D-3 카드와 캐릭터의 제안 말풍선. 화면 모서리에 `설계안`. | “며칠 뒤 자동이체가 있고 출금 계좌의 돈이 부족할 것으로 보이면 캐릭터가 먼저 묻습니다. ‘3일 뒤 자동이체가 있어요. 부족한 금액을 미리 옮겨둘까요?’ 이제 캐릭터의 말은 설명에서 끝나지 않고 행동 선택지로 이어집니다.” |

| 10 | 3:55~4:25 | 상태를 확인하고 결과까지 알려줍니다 | `상태 확인 → 설명 → 제안 → 승인 → 모의 실행 → 결과`가 한 줄로 이어진다. `모의 실행`. | “전체 경험은 이렇게 이어집니다. 금융 상태를 확인하고, 달라진 이유를 설명하고, 가능한 행동을 제안합니다. 사용자가 승인한 경우에만 실행한 뒤 성공, 실패, 미실행을 정확히 알려줍니다. 이번 MVP에서는 실제 금융기관과 연결하지 않고 모의 실행으로 검증합니다.” |
| 11 | 4:25~4:55 | 최근 소비는 캐릭터의 하루에 남습니다 | 카페, 음식점, 영화관, 쇼핑 결제만 짧은 모션으로 바뀐다. `설계안`. | “결제 내역은 배치로 갱신합니다. 카페나 영화관처럼 연결이 분명한 소비만 캐릭터 행동으로 표현합니다. 상호명만으로 무엇을 샀는지 알기 어렵다면 억지로 추측하지 않고 소비 카드만 갱신합니다.” |
| 12 | 4:55~5:25 | 캐릭터의 반응에는 이유가 붙습니다 | 모션 옆에 원인 소비, 예산 잔액, 갱신 시점이 함께 보인다. `설계안`. | “첫 화면에서는 캐릭터가 왜 화가 났는지 알 수 없었습니다. 이 서비스에서는 반응의 원인을 함께 보여줍니다. 어떤 소비가 반영됐는지, 예산이 얼마나 남았는지, 데이터가 언제 갱신됐는지를 바로 확인합니다.” |

| 14 | 5:55~6:25 | 친근할수록 더 조심해야 합니다 | 말풍선 옆에 `확정·예상·미확정`, 근거, 기준 시점이 표시된다. `설계안`. | “캐릭터가 친근하면 AI의 말을 더 쉽게 믿게 됩니다. 그래서 잔액과 예산 소진률, 예정 지출은 정해진 규칙으로 계산하고 AI에는 설명과 선택지만 맡깁니다. 데이터가 부족하면 모른다고 말하며, 자금이 움직이는 행동은 사용자가 승인해야만 처리합니다.” |

| 16 | 6:50~7:10 | 이제 캐릭터의 행동에는 다음 선택이 있습니다 | 1번과 같은 방. 캐릭터 옆에 원인 카드와 행동 선택지가 놓인다. | “처음에는 캐릭터가 화가 나 있어도 이유를 알 수 없었습니다. 이제는 어떤 소비 때문에 반응했는지, 현재 금융 상태가 어떤지, 다음에 무엇을 할 수 있는지가 함께 보입니다. 이 캐릭터는 소비를 보여주는 장식이 아닙니다. 내 금융 생활을 알아보고, 설명하고, 허락받은 일만 처리하는 AI 금융 비서입니다.” |

## 4. 고정 연결 문장

| 전환 | 연결 문장 |
|---|---|
| 익숙한 장면 → 모순 | “캐릭터가 반응한다는 것만으로 돈 관리가 달라질까요?” |
| 첫 해법 → 실패 | “정보는 한곳에 모였지만, 판단은 여전히 사용자가 해야 합니다.” |
| 두 번째 해법 → 실패 | “설명이 쉬워져도 행동까지 이어지지 않으면 알림과 다르지 않습니다.” |
| 문제 재정의 → 반전 | “그래서 캐릭터의 역할을 설명에서 행동 보조까지 넓혔습니다.” |
| 제안 → 승인 | “다만 제안이 곧 실행을 뜻하지는 않습니다.” |
| 작동 원리 → 2차 문제 | “여기서 캐릭터가 친근할수록 더 조심해야 할 문제가 생깁니다.” |
| 보정 → 검증 | “이 안전장치를 지킨 상태에서 한 가지 흐름부터 확인하겠습니다.” |
| 검증 → 첫 장면 회수 | “이제 처음의 방으로 돌아가 보겠습니다.” |

## 5. 발표 화면 규칙

1. 한 슬라이드에는 장면 하나와 질문 하나만 둔다.
2. 슬라이드 7 전에는 완성된 서비스 흐름을 한꺼번에 보여주지 않는다.
3. 슬라이드 8~14에는 `설계안`, 슬라이드 10에는 `모의 실행`을 표시한다.
4. 금융 숫자와 캐릭터의 말을 같은 화면에 두어 반응의 근거를 보여준다.
5. 승인 화면에는 대상, 금액, 시점, 근거와 세 가지 선택지를 함께 둔다.
6. 캐릭터가 사용자를 비난하거나 부자가 될 것처럼 약속하는 장면은 쓰지 않는다.
7. 문제 장면은 검증된 조사 결과가 아니라 기획 단계의 사용자 가설로 말한다.
8. 첫 화면과 마지막 화면은 같은 방을 쓰고, 마지막에 원인과 행동 선택지만 더한다.
9. 채널의 고유 문구, 대상, 사례는 복제하지 않는다.

## 6. 발표에서 빼야 할 내용

- 초반에 핵심 기능을 한꺼번에 나열하는 구성
- 캐릭터 외형과 아이템 종류를 길게 설명하는 구성
- 모든 결제를 캐릭터 모션으로 바꾸는 설명
- 결제 금액이나 거래 횟수에 따라 보상하는 규칙
- AI가 금융 금액을 자유롭게 계산하는 것처럼 들리는 표현
- 사용자의 승인 없이 금융 행동을 처리하는 장면
- 실제 금융기관 연동이 끝난 것처럼 보이는 화면
- 검증 전 가설을 확인된 성과처럼 말하는 표현
- 앞 슬라이드를 다시 요약하는 별도 슬라이드

## 7. 30초 요약본

> “소비를 캐릭터 행동으로 보여주면 눈에는 잘 들어오지만, 사용자가 무엇을 해야 하는지까지 알려주지는 못합니다. 금융 정보를 한곳에 모아도 해석과 판단은 사용자 몫이고, AI가 설명만 늘리면 또 하나의 알림이 됩니다. 그래서 캐릭터를 금융 비서로 바꿨습니다. 소비와 예산을 보고 지금 필요한 행동을 제안하되, 자금이 움직이는 일은 사용자가 승인한 경우에만 처리합니다. 최근 소비는 캐릭터의 하루에 남고, 금융 활동은 액세서리와 방의 변화로 쌓입니다.”

## 8. 질의응답 경계

### 기획안에서 답할 수 있는 질문

| 질문 | 답변 요지 |
|---|---|
| 캐릭터가 왜 필요한가 | 흩어진 금융 상태를 쉬운 말로 설명하고 다음 행동까지 이어 주는 인터페이스다. |
| 모든 결제가 캐릭터 행동으로 바뀌나 | 아니다. 연결이 분명한 일부 소비만 표현한다. |
| AI가 잔액을 직접 계산하나 | 아니다. 금융 금액은 정해진 규칙으로 계산하고 AI는 설명과 선택지를 만든다. |
| 캐릭터가 마음대로 송금하나 | 아니다. 대상, 금액, 시점을 확인한 뒤 사용자가 승인한 행동만 처리한다. |
| 보상 때문에 더 쓰게 되지 않나 | 결제 금액과 횟수에는 보상하지 않고 금융 상태를 확인하고 점검한 활동에 보상한다. |
| 실제 계좌가 연결되나 | MVP는 데모 데이터와 모의 실행으로 검증한다. 실제 연동은 범위 밖이다. |

### 아직 정하지 않은 질문

- 서비스명과 캐릭터명
- 실제 데이터와 금융기관의 연동 범위
- 소비 분류 신뢰도 기준과 사용자가 고친 뒤의 재계산 규칙
- 재화 지급량과 아이템 가격
- 개인정보의 구체적인 보관·삭제 정책
- 실제 송금 또는 자동이체 실행 방식
- MVP 정량 성공 기준

모르는 항목은 발표에서 정해졌다고 말하지 않는다.
