# 기획 발표 서사

발표 제목: 관리는 알겠는데, 왜 아무도 계속하지 못할까

부제: 내 소비로 살아 움직이며 필요한 일까지 처리하는 캐릭터 AI 금융 비서

예상 길이: 약 7분

상태: 설계안

> 「신비한 건축사전」의 고유 문장이나 소재는 가져오지 않는다. 익숙한 장면에서 시작해 두 번의 해법과 실패를 거친 뒤 문제를 다시 정의하고, 작동 원리와 약점을 설명한 다음 첫 장면으로 돌아오는 흐름만 참고한다.

## 1. 발표의 핵심 반전

> 캐릭터는 꾸미기 요소가 아닙니다. 매일 앱을 열 이유를 만드는 동시에, 필요한 순간 먼저 묻고 허락받아 금융 업무까지 처리합니다.

캐릭터를 넣은 이유는 두 가지다. 금융 관리는 원래 재미가 없어서 계속되지 않고, 관리를 잘해도 실제 행동은 사용자가 직접 해야 한다. 캐릭터는 이 두 구멍을 동시에 메운다. 발표에서는 이 결합을 슬라이드 한 장에서 보여준다.

## 2. 전체 흐름

```text
익숙한 장면: 예산 앱을 깔았지만 2주 만에 열지 않는다 (1)
→ 모순: 관리해야 한다는 건 알지만 아무도 계속하지 못한다 (2)
→ 대가: 안 보는 사이 자동이체가 잔액 부족으로 실패한다 (3)
→ 첫 해법: 정보를 한 화면에 모은다 (4)
→ 실패: 화면은 정리됐지만 열지 않으면 아무 일도 일어나지 않는다 (5)
→ 두 번째 해법: AI가 소비를 분석해 알려준다 (6)
→ 실패: 알림이 하나 늘고 행동은 여전히 사용자 몫이다 (7)
→ 문제 재정의: 부족한 것은 정보가 아니라 계속 올 이유와 마지막 실행이다 (8)
→ 중앙 반전: 내 소비로 살아 움직이는 캐릭터가 그 일까지 대신 묻는다 (9)
→ 작동 원리: 결제 반영 → 상태 계산 → 설명 → 제안 → 승인 → 실행 → 결과 (10~12)
→ 계속 오는 이유: 관리한 기록이 캐릭터와 방에 남는다 (13)
→ 2차 문제와 보정: 친근할수록 과신하므로 계산과 설명을 분리하고 승인을 받는다 (14)
→ 검증: 데모 데이터와 모의 실행으로 한 흐름을 끝까지 확인한다 (15)
→ 첫 장면 회수: 열지 않던 앱을 매일 열고, 놓쳤던 자동이체를 미리 막는다 (16)
```

## 4. 고정 연결 문장

| 전환 | 연결 문장 |
|---|---|
| 익숙한 장면 → 모순 | “의지가 부족해서 그만둔 걸까요?” |
| 모순 → 대가 | “문제는 안 하는 동안에도 돈은 움직인다는 점입니다.” |
| 첫 해법 → 실패 | “잘 만든 화면도 열지 않으면 그대로입니다.” |
| 두 번째 해법 → 실패 | “분석이 정확해질수록 알림만 늘어납니다.” |
| 문제 재정의 → 반전 | “그래서 채워야 할 칸은 정보가 아니라 계속 올 이유와 마지막 실행이었습니다.” |
| 반전 → 작동 원리 | “이 두 가지가 실제로 어떻게 굴러가는지 보겠습니다.” |
| 제안 → 승인 | “다만 제안이 곧 실행을 뜻하지는 않습니다.” |
| 작동 원리 → 2차 문제 | “여기서 캐릭터가 친근할수록 커지는 위험이 있습니다.” |
| 보정 → 검증 | “이 안전장치를 지킨 상태에서 한 흐름부터 확인하겠습니다.” |
| 검증 → 첫 장면 회수 | “처음의 홈 화면으로 돌아가 보겠습니다.” |

## 5. 발표 화면 규칙

1. 한 슬라이드에는 장면 하나와 질문 하나만 둔다.
2. 슬라이드 9의 반전 전까지 캐릭터를 해법으로 소개하지 않는다. 1번부터 8번까지는 사용자가 겪는 문제만 다룬다.
3. 슬라이드 9에서는 보는 재미와 실제 실행을 같은 화면에 나란히 둔다. 두 장으로 나누면 반전이 흐려진다.
4. 슬라이드 10, 11, 13, 14에는 `설계안`, 슬라이드 12에는 `모의 실행`을 표시한다.
5. 캐릭터의 반응 옆에는 원인 소비와 예산 상태를 항상 함께 보여준다.
6. 승인 화면에는 대상, 금액, 시점, 근거와 세 가지 선택지를 함께 둔다.
7. 캐릭터가 사용자를 비난하거나 부자가 될 것처럼 약속하는 장면은 쓰지 않는다.
8. 문제 장면은 기획 단계의 사용자 가설로 말하고 검증된 조사 결과처럼 단정하지 않는다. 자동이체 실패와 연체처럼 제도상 정해진 결과만 사실로 말한다.
9. 첫 화면과 마지막 화면은 같은 홈 화면을 쓰고, 마지막에 접속 기록과 막아낸 출금만 더한다.
10. 채널의 고유 문구, 대상, 사례는 복제하지 않는다.

## 6. 발표에서 빼야 할 내용

- 캐릭터를 문제로 놓고 시작하는 구성. 캐릭터는 해법 자리에만 등장한다
- 우리 캐릭터 표현을 먼저 깎아내린 뒤 나중에 되살리는 구성
- 초반에 핵심 기능을 한꺼번에 나열하는 구성
- 캐릭터 외형과 아이템 종류를 길게 설명하는 구성
- 모든 결제를 캐릭터 모션으로 바꾸는 설명
- 결제 금액이나 거래 횟수에 따라 보상하는 규칙
- AI가 금융 금액을 자유롭게 계산하는 것처럼 들리는 표현
- 사용자의 승인 없이 금융 행동을 처리하는 장면
- 실제 금융기관 연동이 끝난 것처럼 보이는 화면
- 근거 없는 통계, 검증 전 가설을 확인된 성과처럼 말하는 표현
- 앞 슬라이드를 다시 요약하는 별도 슬라이드

## 7. 30초 요약본

> “예산 앱은 방법을 몰라서 그만두는 게 아닙니다. 매일 해야 하는데 재미가 없어서 2주면 열지 않게 되고, 그 사이 자동이체가 잔액 부족으로 실패합니다. 정보를 잘 모아도 열지 않으면 그대로고, AI가 분석해도 알림이 하나 늘 뿐 실행은 사용자 몫입니다. 그래서 캐릭터에게 두 가지를 맡겼습니다. 제 소비를 따라 살아 움직여 매일 열 이유를 만들고, 필요한 순간 먼저 물어 허락받은 일까지 처리합니다. 자금이 움직이는 행동은 승인 없이 실행하지 않고, 잘 관리한 기록만 캐릭터와 방에 남습니다.”

## 8. 질의응답 경계

### 기획안에서 답할 수 있는 질문

| 질문 | 답변 요지 |
|---|---|
| 왜 캐릭터인가 | 관리가 이어지지 않는 이유는 재미가 없어서다. 캐릭터는 매일 열 이유를 만들고, 그 접점에서 필요한 행동까지 잇는다. |
| 기존 가계부와 무엇이 다른가 | 가계부는 기록과 분석에서 끝난다. 캐릭터는 승인을 받아 자동이체 자금 준비 같은 실제 업무를 처리한다. |
| 다마고치류 앱과 무엇이 다른가 | 캐릭터의 반응이 임의 연출이 아니라 실제 결제와 예산에서 나오고, 금융 행동으로 이어진다. |
| 모든 결제가 캐릭터 행동으로 바뀌나 | 아니다. 연결이 분명한 일부 소비만 표현하고 나머지는 소비 카드만 갱신한다. |
| AI가 잔액을 직접 계산하나 | 아니다. 금융 금액은 정해진 규칙으로 계산하고 AI는 설명과 선택지를 만든다. |
| 캐릭터가 마음대로 송금하나 | 아니다. 대상, 금액, 시점을 확인한 뒤 사용자가 승인한 행동만 처리한다. |
| 보상 때문에 더 쓰게 되지 않나 | 결제 금액과 횟수에는 보상하지 않고 예산 확인과 점검, 제안 검토에만 보상한다. |
| 실제 계좌가 연결되나 | MVP는 데모 데이터와 모의 실행으로 검증한다. 실제 연동은 범위 밖이다. |

### 아직 정하지 않은 질문

- 서비스명과 캐릭터명
- 실제 데이터와 금융기관의 연동 범위
- 소비 분류 신뢰도 기준과 사용자가 고친 뒤의 재계산 규칙
- 재화 지급량과 아이템 가격
- 개인정보의 구체적인 보관·삭제 정책
- 실제 송금 또는 자동이체 실행 방식
- MVP 정량 성공 기준과 리텐션 목표치

모르는 항목은 발표에서 정해졌다고 말하지 않는다.
